# Working in this repository

**`tokens.json` is the only place a value is typed.** Everything in `build/` is
generated by `scripts/build.mjs`. Never edit `build/` — the change will vanish
on the next build and CI will fail on the stale diff.

## After changing tokens.json

```bash
npm run build     # regenerate build/, and commit the result
npm run check     # validate only, no writes
```

Both are dependency-free and run on a clean checkout. `build/` is committed so
consumers can install straight from a git tag.

## Where things belong

- **A value** → `tokens.json`.
- **A prose rule** → `DESIGN-SYSTEM.md`, referencing tokens by name, never by
  value. If a hex appears in two places, one of them is wrong.
- **Why a rule has its shape** → `DECISIONS.md`, newest first.
- **A new constraint worth enforcing** → a rule in `tokens.json` plus a check in
  `scripts/build.mjs`. A guideline nothing checks will drift.

## Rules for changing things

**Adding a token** is a design decision. Give it a real `use` string, and add a
`minContrast` entry if it carries text.

**Retiring a token** means moving it to the `retired` array with a `replacedBy`
and a `reason`. Do not delete it — the build checks that retired names have not
come back, and deleting the entry loses the record of why it went.

**Retired names must match the generated name exactly**, including the
namespace: `--color-border-default`, not `--border-default`. A retired entry
whose name never appears in the output is a check that silently passes forever.

## Releasing

Bump `meta.version` in `tokens.json` **and** `version` in `package.json`, add a
`CHANGELOG.md` entry, then tag `vX.Y.Z`. CI asserts the tag and `meta.version`
agree — a tag publishing a different version means anyone pinned to it quietly
installed something else.

## House style

Comments explain *why*, not *what*. The generated CSS carries its reasoning
inline because that is where someone reads it. Several checks in
`build.mjs` cite the specific failure they exist to prevent; keep that when
adding more.
